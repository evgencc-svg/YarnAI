## 7. Действительно обнаруженные проблемы

- **Риск потери результатов:** значительная поздняя разработка не сохранена в Git. Наличие папки не равно проверенной резервной копии.
- **Окружение:** `python`/`py` указывают на недоступные WindowsApps-запуски. Проектная `.venv` (Python 3.12.13) не стартует: uv trampoline, OS error 4551. Точная текущая причина не диагностирована; в истории упоминалась App Control. Защита системы не менялась.
- **Тестовая полнота:** в рабочем Python нет `reportlab`; полный набор без исключений не пройден. В старой `.venv` каталог пакета есть, но работоспособность этого окружения не подтверждена.
- **Документация расходится с кодом:** README одновременно описывает отсутствие аккаунтов/серверной базы и необязательные облачные аккаунты; утверждает отсутствие фотоанализа, хотя контролируемый фотоанализ уже реализован и испытан. Паспорта с датой 02.09 не охватывают продолжение 30.09. Текущий `PROJECT_STATE` содержит последовательные исторические записи, включая уже преодолённые blockers.
- **Адреса проекта:** принятое ранее правило основной среды 8000 сосуществует с последней явной записью реального поло на 8030. Это разные browser origin — отдельные хранилища. Нельзя просто открыть 8000 и объявить данные потерянными или перенести их без проверки.
- **Граница доказательств:** реальный расчёт, физическое изделие и готовность к продаже пока не подтверждены. Нового воспроизводимого дефекта расчётов в выполненных тестах не обнаружено.

Отдельный исторический HTTP 422 рекомендации пряжи не имеет сохранённой точной причины validation. Его нельзя объявить исправленным или приписать текущему ручному пути без воспроизведения. Повтор платного вызова аудит не разрешает.

## 8. Можно ли продолжать без переписывания

**Да.** Новые тесты и запуск сервера подтверждают сохранность значительной части технической основы. Нет доказательства, что замена архитектуры даст нужный пользовательский результат быстрее. Главный текущий разрыв — сохранность фактических данных и незакрытая реальная приёмка, а не отсутствие ещё одного программного слоя.

Не проверено: побайтовая неизменность пользовательских данных относительно сентября, состояние удалённого GitHub, физическая точность плана, безопасность всех зависимостей и публичная эксплуатация. Процент готовности без этих доказательств не назначается.
