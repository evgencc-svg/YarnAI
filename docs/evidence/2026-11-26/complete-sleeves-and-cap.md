В лицевых рядах прибавок M1R означает прибавку из протяжки с наклоном вправо, M1L — влево. Убавки оката выполняются двумя вместе вправо в начале и двумя вместе влево в конце. Каждый ряд с фиксированным номером содержит сторону полотна, действие и остаток. Число рядов резинки и прямых участков до замера неизвестно. В источнике указана плотность только для лицевой глади — 20 п. и 27 р. на 4″ = 10,16 см.

## Сравнение с проймой

На снимках раскрытого рукава видны конец прямого участка и первые ряды оката. Для 52″ первые три ряда дают 82, 75 и 73 петли, для 40″ — 71, 67 и 65. [Экран 52″](anthony-52-sleeve-cap.png) · [Экран 40″](anthony-40-sleeve-cap.png)

| По издательской плотности | 52″ | 40″ |
| --- | ---: | ---: |
| Высота до горизонтального закрытия верха оката | 62 ряда, 23,33 см | 58 рядов, 21,83 см |
| Независимая сверка высоты на чертеже, стр. 3 | 9¼″, 23,50 см | 8½″, 21,59 см |
| Глубина проймы до наружного края плеча | 11″, 27,94 см | 9½″, 24,13 см |
| Один край проймы, от подмышки до плеча | 32,74 см | 26,78 см |
| Половина оката до середины верхнего края | 35,21 см | 30,85 см |
| Разность по полному контуру, до округления отдельных длин | +4,94 см | +8,13 см |

Для одного рукава берётся один наружный край переда и один спинки. При взгляде с лица деталей левому рукаву соответствуют правый край переда и левый край спинки, правому — противоположные. Обе половины авторского оката симметричны. Подмышечные закрытия на каждой стороне сопоставлены с тем же размером корпуса. Для оценки длины горизонталь начальной ступени складывается с высотой двух рядов. Группа парных убавок и две верхние ступени оцениваются по диагонали по ширине и высоте группы. На корпусе учитывается прямой остаток глубины, на окате — половина горизонтального закрытия верха. Разность показывает, сколько дополнительной длины модель даёт по окату. Допуск автора и поведение реального полотна при припосадке неизвестны.

## Интеграция и испытания

- Штатный импорт и сохранённый текст исходника → проекция столбца → полное чтение команд манжеты, прибавок и оката. Контроль петель и доступного края повторно использует расчёт операций поло; для швов выделена общая формула из расчёта геометрии втачного рукава. Авторские интервалы берутся непосредственно из PDF. Две детали имеют собственное имя и одинаковый для этого источника порядок рядов.
- 26 целевых автоматических проверок прошли. Проверены оба размера и обе стороны, отдельная первая прибавка, изменение спиц, каждое промежуточное состояние и восстановление записанных действий. Добавлен третий искусственный столбец с другим числом рядов и петель. Искажения команд, интервалов, наклонов и сторон, добавление или пропуск операции, неверный остаток, преждевременное закрытие, неправильный размер, несовпадающие подрезы и недостаточная глубина отклонены.
- В Edge на отдельном адресе 127.0.0.1:18726 созданы две карточки через форму, загружен оригинал, введён только размер. В раскрытых списках независимо сверены все строки, направления операций, остатки и текст обоих сравнений. Перезагрузка и новый процесс браузера с открытием из списка дали идентичные результаты. Экспорт каждой карточки содержал исходный PDF байт в байт и соответствующий размер.
- Копии двух уже сохранённых карточек 4C проверены отдельно на их прежнем адресе 127.0.0.1:18723. Без повторного импорта появились рукава, обе старые детали корпуса и держатель на 41 п. сохранились. После следующего перезапуска совпал полностью развёрнутый текст каждой карточки. Тестовый PDF без страницы рукавов дал сообщение об отсутствующем разделе и ноль рассчитанных рядов рукавов. Тестовые профили, снимки, развёрнутый текст и резервные копии находятся локально в `tmp/cycle4d-sleeves-1126` основной копии.
- Исправлены обнаруженные расхождения прежних проверок интерфейса. Проверка сохранённых карточек искала ссылку в последнем дочернем элементе, где уже находилась группа действий с резервной копией. Теперь проверяются сама ссылка, её прежний точный адрес и отсутствие ссылок продолжения у завершённой карточки. Проверка страницы разбора сверяет полный фактический порядок скриптов. Ссылка на оригинал перенесена к сведениям об издательской поправке, проверка запрета внешних адресов в коде контроллера сохранена.

## Итоги регрессии

- Штатная команда `npm test` со всеми предварительными наборами завершилась успешно. В журнале 2327 успешных исполнений проверок. Сборка `npm run build` и проверка разницы Git прошли.
- Первый расширенный прогон, начатый до исправления прежних проверок, дал 3030 из 3036. Шесть сбоев приходились на поиск элементов карточек. После исправления все восемь проверок этого файла прошли с сохранением исходных требований к навигации.
- На коммите реализации запущены все 140 файлов JavaScript (3062 проверки, включая новые 26). При десяти параллельных процессах **3061 прошла, 1 вышла за лимит времени**. Прежняя проверка текста примерно в миллион знаков заняла 8,48 с при пороге 5 с. Затем весь файл выполнен отдельно: **34 из 34**, та же проверка заняла 2,85 с. В штатном наборе она заняла 4,13 с. Порог сохранён. Общий параллельный запуск завершился с кодом 1.
- В первом полном прогоне Python выявлены два расхождения на странице разбора — в перечне подключённых скриптов и в расположении прямой ссылки на PDF. После исправления полный повтор дал **1643 прошли, 1 пропущена**, 71,97 с. Список скриптов проверяется в порядке загрузки, для каждого проверяется доступность по HTTP.
- Поло: 36 шагов в отдельном проекте Edge, включая планки, воротник, сборку, перезагрузку и повторное открытие. Barley Field: отдельная копия тестового профиля Chrome, повторное открытие сохранённой карточки, точное совпадение всех 14 прежних шагов для печати. Для последнего сценария исправлены вызов вспомогательного драйвера с аргументом повторного открытия и режим запуска тестового окна Chrome.
