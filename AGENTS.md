# Yarn AI: обязательные правила проекта

## Источники истины

Перед любой работой читать в таком порядке:

1. `docs/project-control/PROJECT_STATE.md` — только текущая подтверждённая правда.
2. `.agents/skills/yarn-ai-workflow/SKILL.md` — процедура работы.
3. Только необходимые reference-файлы навыка.
4. Единственный файл `docs/plans/ACTIVE_*.md`, если он существует.

История решений хранится в `docs/project-control/DECISION_LOG.md`, а фактическое время и переделки — в `docs/project-control/TIME_LEDGER.md`. Исторические отчёты и обсуждения не являются текущей истиной без подтверждения в `PROJECT_STATE.md`.

## Коммерческая цель первой версии

Существующая схема или PDF → подтверждённые исходные данные → адаптация под размер, пряжу, спицы и плотность → объяснение изменений → исполнимый план вязания.

Не реализовывать другие функции до пользовательского принятия этой цепочки.

## Правила проекта

- Исходную схему и пользовательскую адаптацию хранить отдельно.
- Каждое итоговое число связывать с источником, решением пользователя или формулой.
- Детерминированные расчёты выполнять кодом, а не свободным ответом модели.
- Не изобретать отсутствующие инструкции; неопределённость показывать прямо.
- Не добавлять новый Stage ради красивой архитектуры.
- Не добавлять сервис, модель, зависимость или слой без необходимости для текущего блока.
- Будущие функции учитывать только местом подключения.
- Не перекладывать технические решения на Евгения.
- Не считать успешную сборку, число компонентов или число тестов готовым продуктом.
- Проверять настоящий интерфейс и реальные данные.
- Следующий блок начинать только после явного подтверждения предыдущего Евгением.

## Порядок работы

1. Прочитать `PROJECT_STATE.md`.
2. Назвать один пользовательский результат и границу задачи.
3. Проверить реализуемость; при неизвестности провести короткое испытание.
4. Для сложной работы создать или обновить один живой план.
5. Реализовать только один утверждённый блок.
6. Выполнить автоматические проверки.
7. Запустить настоящий продукт и проверить живой интерфейс.
8. Проверить сохранение после перезагрузки и повторного открытия.
9. Провести пользовательскую проверку человеческим способом.
10. Обновить `PROJECT_STATE.md`, `DECISION_LOG.md` и `TIME_LEDGER.md`.
11. Остановиться и получить подтверждение Евгения.

Статусы: `PASS` — вся граница доказана; `PARTIAL` — часть работает, но обязательный разрыв остаётся; `FAIL` — обязательный результат не работает или неверен; `BLOCKED` — названа точная внешняя причина, делающая работу невозможной.
