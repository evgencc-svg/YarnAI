# DOMAIN MODEL

Версия: 0.1

Статус: Черновик

## Назначение

Этот документ описывает мир продукта YarnAI: какие сущности в нём существуют, зачем они нужны и как связаны по смыслу.

Это не структура базы данных, не программная модель и не схема хранения. Количество, обязательность и границы сущностей остаются продуктовыми понятиями до принятия соответствующих решений.

## Основные сущности

### User

**Что это**

Человек, который обращается к YarnAI со своим намерением, контекстом и текущей работой.

**Для чего существует**

Чтобы сопровождение было связано с реальным человеком и его подтверждённым опытом, а не с абстрактным уровнем подготовки.

**С чем связана**

Learning State, Project, Session, Intent, State, Memory, Journey.

**Что может содержать**

Подтверждённые предпочтения сопровождения, важные ограничения, доступные проекты и ссылки на сведения, которые пользователь сообщил о себе.

### Learning State

**Что это**

Картина подтверждённых умений, понимания, затруднений и способов объяснения, которые подходят конкретному User.

**Для чего существует**

Чтобы выбирать необходимую глубину сопровождения по конкретному Skill, не присваивая пользователю общий постоянный уровень.

**С чем связана**

User, Skill, Skill Level, Review, Checkpoint, Recommendation, Memory.

**Что может содержать**

Подтверждённые навыки, наблюдаемые затруднения, ошибочные представления, успешные способы объяснения, источник и уверенность каждого вывода.

### Project

**Что это**

Контекст работы над конкретным Item от замысла до завершения или осознанной остановки.

**Для чего существует**

Чтобы объединять цель, материалы, Pattern, Current Step, Progress и историю решений вокруг одной работы.

**С чем связана**

User, Item, Pattern, Reference Image, Photo, Video, Current Step, Project History, Progress, Checkpoint, Mistake.

**Что может содержать**

Ожидаемый результат, ограничения, используемые материалы и инструменты, текущую точку, выполненные шаги, открытые проблемы и критерии завершения.

### Item

**Что это**

Вязаная вещь, которую пользователь планирует, создаёт, исправляет, проверяет или завершил.

**Для чего существует**

Чтобы у Project был конкретный предметный результат.

**С чем связана**

Project, Pattern, Reference Image, Technology, Review, Photo.

**Что может содержать**

Назначение, тип вещи, размеры, форму, составные части, ожидаемые признаки и фактическое состояние.

### Technology

**Что это**

Способ выполнения отдельного действия, участка работы или заключительной обработки.

**Для чего существует**

Чтобы различать возможные способы достижения результата и объяснять последствия выбора.

**С чем связана**

Pattern, Skill, Recommendation, Alternative, Current Step, Item.

**Что может содержать**

Название способа, область применения, необходимые условия, ожидаемый результат, ограничения, риски и возможные альтернативы.

### Pattern

**Что это**

Текстовое, графическое или смешанное описание того, как изготовить Item.

**Для чего существует**

Чтобы задавать последовательность действий, требования и контрольные ориентиры проекта.

**С чем связана**

Project, Item, Technology, Current Step, Reference Image, Mistake, Review.

**Что может содержать**

Материалы, обозначения, размеры, последовательность шагов, схемы, контрольные значения и сведения об источнике.

### Skill

**Что это**

Конкретное умение пользователя понять или выполнить определённое действие.

**Для чего существует**

Чтобы описывать способности точечно и связывать сопровождение с реальной задачей.

**С чем связана**

Learning State, Skill Level, Technology, Review, Checkpoint, Recommendation.

**Что может содержать**

Название умения, наблюдаемые признаки выполнения, условия применения, типичные затруднения и критерии подтверждения.

### Skill Level

**Что это**

Степень подтверждённого владения конкретным Skill.

**Для чего существует**

Чтобы выбирать глубину объяснения и необходимость проверки по отдельному умению, а не по общему ярлыку пользователя.

**С чем связана**

Skill, Learning State, Checkpoint, Review, Confidence.

**Что может содержать**

Текущий рабочий уровень владения навыком, подтверждающие наблюдения, ограничения вывода и дату последней проверки.

### Session

**Что это**

Отдельный период взаимодействия User с YarnAI вокруг одного или нескольких связанных намерений.

**Для чего существует**

Чтобы понимать границы текущего разговора и при этом сохранять связь с долгосрочным Project и Journey.

**С чем связана**

User, Intent, State, Project, Recommendation, Memory, Journey.

**Что может содержать**

Входное сообщение, текущие Intent и State, заданные уточнения, данные, рекомендации, результаты проверок и причину завершения взаимодействия.

### Intent

**Что это**

Результат, которого User хочет добиться прямо сейчас.

**Для чего существует**

Чтобы перед любым сопровождением определить, зачем человек обратился, и выбрать соответствующий Scenario.

**С чем связана**

User, State, Session, Project, Scenario, Recommendation, Progress.

**Что может содержать**

Название намерения, формулировку пользователя, рабочую интерпретацию, подтверждение или неопределённость определения и ожидаемый результат.

### State

**Что это**

Текущая фактическая ситуация User и его работы.

**Для чего существует**

Чтобы сопровождать человека по происходящему сейчас, а не по предполагаемому уровню знаний.

**С чем связана**

User, Intent, Project, Current Step, Session, Scenario, Progress.

**Что может содержать**

Название состояния, наблюдаемые признаки, цель состояния, необходимые сведения, критерий завершения и возможные переходы.

### Photo

**Что это**

Фотография проекта, изделия, материала, инструмента, Pattern или ожидаемого результата.

**Для чего существует**

Чтобы дать визуальные сведения для Review, диагностики и проверки результата.

**С чем связана**

Project, Item, Reference Image, Review, Mistake, Computer Vision Result, Project History.

**Что может содержать**

Само изображение, описание того, что на нём нужно проверить, ракурс, масштаб, время создания и ограничения качества.

### Video

**Что это**

Запись движения, процесса или изменения работы во времени.

**Для чего существует**

Чтобы наблюдать способ выполнения, который нельзя надёжно понять по одному Photo.

**С чем связана**

Project, Technology, Skill, Review, Computer Vision Result, Project History.

**Что может содержать**

Запись действия, описание проверяемого движения, момент проекта, ориентацию, качество изображения и ограничения наблюдения.

### Reference Image

**Что это**

Изображение желаемого Item или важной детали результата.

**Для чего существует**

Чтобы уточнять ожидания и критерии сходства, не принимая изображение за подтверждённый способ изготовления.

**С чем связана**

Item, Project, Pattern, Photo, Review, Confidence.

**Что может содержать**

Источник, изображение, признаки, которые важны пользователю, допустимые отличия и неизвестные сведения о конструкции.

### Current Step

**Что это**

Место в Project, на котором User находится сейчас.

**Для чего существует**

Чтобы связать вопрос, рекомендацию и проверку с конкретной точкой работы.

**С чем связана**

Project, Pattern, Technology, Mistake, Checkpoint, Recommendation, Progress.

**Что может содержать**

Название шага, ожидаемый результат, уже выполненные действия, фактический результат, открытые вопросы и ближайшую контрольную точку.

### Recommendation

**Что это**

Обоснованное предложение следующего действия для конкретного Intent, State и контекста.

**Для чего существует**

Чтобы помочь User продвинуться к результату, не скрывая предположения и риски.

**С чем связана**

Intent, State, Project, Current Step, Confidence, Alternative, Checkpoint, Review.

**Что может содержать**

Предлагаемое действие, основание, ожидаемый результат, предположения, риски, уровень уверенности, альтернативы и способ проверки.

### Confidence

**Что это**

Оценка того, насколько доступные сведения поддерживают отдельный вывод или Recommendation.

**Для чего существует**

Чтобы показать границы надёжности и определить, можно ли рекомендовать действие или сначала нужны дополнительные данные.

**С чем связана**

Recommendation, Review, Alternative, Computer Vision Result, Skill Level, Reference Image.

**Что может содержать**

Рабочую оценку, основание, неизвестные факторы, цену возможной ошибки и сведения, которые могут изменить уверенность.

### Alternative

**Что это**

Другой обоснованный путь действий с отличающимися последствиями или условиями выбора.

**Для чего существует**

Чтобы User мог принять осмысленное решение, когда единственного правильного пути нет.

**С чем связана**

Recommendation, Technology, Intent, Confidence, Project.

**Что может содержать**

Описание варианта, подходящие условия, ожидаемый результат, преимущества, ограничения, риски и различия относительно других вариантов.

### Mistake

**Что это**

Подтверждённое расхождение между фактической работой и выбранным корректным результатом.

**Для чего существует**

Чтобы локализовать проблему, понять её последствия и выбрать способ исправления.

**С чем связана**

Project, Current Step, Pattern, Photo, Review, Recommendation, Project History.

**Что может содержать**

Наблюдаемый симптом, подтверждённую или предполагаемую причину, место возникновения, последствия, статус исправления и подтверждающие сведения.

### Checkpoint

**Что это**

Запланированный момент проверки перед дальнейшим действием.

**Для чего существует**

Чтобы обнаружить расхождение до накопления ошибки или перехода к трудно обратимому шагу.

**С чем связана**

Project, Current Step, Review, Recommendation, Progress, Learning State.

**Что может содержать**

Что нужно проверить, ожидаемые признаки, необходимые сведения, результат проверки и допустимые дальнейшие переходы.

### Review

**Что это**

Проверка работы или результата по понятным критериям.

**Для чего существует**

Чтобы отличить правильное выполнение, допустимую вариацию, неизвестность и Mistake.

**С чем связана**

Project, Item, Current Step, Photo, Video, Checkpoint, Confidence, Recommendation.

**Что может содержать**

Объект проверки, критерии, наблюдаемые факты, вывод, ограничения, уверенность и следующий шаг.

### Computer Vision Result

**Что это**

Наблюдения, полученные при рассмотрении Photo или Video средствами компьютерного зрения.

**Для чего существует**

Чтобы использовать видимые признаки в решении, не смешивая наблюдение с окончательным диагнозом.

**С чем связана**

Photo, Video, Review, Mistake, Confidence, Recommendation.

**Что может содержать**

Обнаруженные признаки, область изображения, ограничения качества, возможные интерпретации, уверенность и запрос на дополнительный ракурс.

### Project History

**Что это**

Последовательность значимых событий, решений и проверок внутри Project.

**Для чего существует**

Чтобы восстановить ход работы, причины изменений и место возможного расхождения.

**С чем связана**

Project, Current Step, Recommendation, Mistake, Checkpoint, Review, Photo, Video.

**Что может содержать**

Изменения проекта, выполненные шаги, рекомендации, результаты проверок, ошибки, исправления, замены материалов и переходы между State.

### Memory

**Что это**

Сохранённые подтверждённые сведения, необходимые для продолжения сопровождения.

**Для чего существует**

Чтобы не терять значимый контекст между Session и не заставлять User повторять уже известное без причины.

**С чем связана**

User, Learning State, Session, Project, Project History, Journey.

**Что может содержать**

Подтверждённые предпочтения, ограничения, значимый контекст проектов, выводы Learning State, источники сведений и признаки устаревания.

### Progress

**Что это**

Подтверждённое продвижение к результату, соответствующему текущему Intent.

**Для чего существует**

Чтобы оценивать реальное изменение работы или понимания, а не активность внутри продукта.

**С чем связана**

Intent, State, Project, Current Step, Checkpoint, Review, Journey.

**Что может содержать**

Достигнутый результат, пройденную контрольную точку, подтверждение, оставшиеся препятствия и следующий ожидаемый результат.

### Journey

**Что это**

Весь нелинейный путь User через проекты, состояния, намерения и периоды взаимодействия.

**Для чего существует**

Чтобы видеть развитие опыта целиком, не превращая его в обязательный линейный курс.

**С чем связана**

User, Project, Session, Intent, State, Progress, Memory.

**Что может содержать**

Значимые проекты, смены Intent, переходы между State, завершённые результаты, остановки, возвращения и подтверждённые изменения опыта.

### Scenario

**Что это**

Логика сопровождения, выбранная после определения Intent, State и текущего контекста.

**Для чего существует**

Чтобы связать необходимую информацию, действия системы, критерий проверки и возможный переход.

**С чем связана**

Intent, State, Learning State, Project, Recommendation, Checkpoint, Session.

**Что может содержать**

Условия применения, необходимые сведения, порядок продуктовых действий, точки остановки, критерий завершения и возможные следующие State.

## Связи между сущностями

- User имеет один актуальный Learning State как совокупность подтверждённых сведений о разных Skill.
- Learning State принадлежит User, а не Project.
- Learning State может использовать свидетельства из разных Project, Session, Review и Checkpoint.
- User может иметь несколько Project.
- В текущей рабочей модели Project создаётся вокруг одного целевого Item.
- Item может быть связан с Pattern и одним или несколькими Reference Image.
- Project может использовать Pattern, но наличие Pattern не обязательно для любого Intent.
- Pattern описывает Technology, последовательность действий и ожидаемые контрольные результаты для Item.
- Project имеет Current Step, когда работа уже начата.
- Current Step относится к конкретному Project.
- Mistake относится к определённому Current Step или участку Project.
- Mistake может быть обнаружена через Review, Photo, Video или Checkpoint.
- Project имеет много Photo и может иметь много Video.
- Photo и Video могут относиться к Current Step, Mistake, Review или завершённому Item.
- Computer Vision Result создаётся на основании конкретного Photo или Video.
- Computer Vision Result содержит наблюдения, но сам по себе не является окончательным Review или диагнозом Mistake.
- Review использует критерии Project, Item, Pattern или Current Step.
- Review может подтвердить Progress, выявить Mistake или показать, что данных недостаточно.
- Checkpoint относится к Project и проверяет результат конкретного этапа.
- Recommendation создаётся для сочетания Intent, State и текущего контекста.
- Recommendation может иметь Confidence и несколько Alternative.
- Alternative относится к одному вопросу решения и сравнивается по последствиям для Intent.
- Confidence относится к конкретному выводу, Recommendation, Review или Computer Vision Result, а не к User целиком.
- Session принадлежит User и может быть связана с одним или несколькими Intent.
- Session может относиться к Project, но не всякая Session требует существующего Project.
- State определяется в контексте текущего Intent и фактической ситуации.
- Scenario выбирается после определения Intent и State.
- Scenario использует Learning State для выбора глубины сопровождения, но не выбирается по общему уровню User.
- Project History принадлежит Project и фиксирует значимые изменения, проверки и решения.
- Memory связывает значимый контекст между Session.
- Memory может содержать подтверждённые выводы Learning State и ссылки на Project History.
- Progress оценивается относительно текущего Intent и ожидаемого результата.
- Journey принадлежит User и объединяет несколько Project, Session, Intent, State и подтверждённый Progress.
- Переход State не означает автоматического изменения Learning State.
- Изменение Learning State требует нового подтверждающего свидетельства.

## Открытые вопросы

Ниже перечислены вопросы, которые затрагивают предметную модель, но ещё не утверждены архитектурно.

### Границы продукта

- Охватывает ли продукт крючок, спицы или оба направления — D-002.
- Какие виды Item и Project входят в первую подтверждённую область продукта.
- Может ли один Project иметь несколько Item или всегда строится вокруг одного целевого Item.
- Где проходит граница между Project, отдельной задачей внутри Project и Journey.
- Когда новый замысел становится новым Project, а когда остаётся изменением текущего.

### Результат и качество

- Что считается успешно завершённым Item — D-003.
- Какой уровень совпадения Item с Reference Image достаточен — D-004.
- Как отличать Mistake от допустимой вариации и осознанного изменения.
- Какие критерии Review обязательны для разных видов Item.
- Когда Progress считается подтверждённым.
- Какие Checkpoint обязательны, а какие зависят от риска и Intent.

### Уверенность и остановка

- Как выражается Confidence и какой её уровень допускает Recommendation — D-005.
- Когда система обязана сказать «не знаю» — D-006.
- Как учитывать цену ошибки при оценке Confidence.
- Может ли Recommendation иметь разные уровни уверенности для отдельных утверждений.
- Когда Computer Vision Result достаточен для Review, а когда требуется дополнительное свидетельство.

### Объяснение и сопровождение

- Что имеет приоритет при конфликте простоты и технологической точности — D-007.
- До какого момента продолжается сопровождение User — D-008.
- Где проходит граница между Recommendation, объяснением Technology и обучением Skill.
- Как определяется достаточная глубина объяснения по Learning State.
- Может ли один Scenario обслуживать несколько Intent или каждый Intent требует отдельной логики.
- Какой набор State и переходов должен считаться утверждённым.
